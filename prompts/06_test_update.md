=== SYSTEM ===
You are a senior PHP test engineer working on a Magento 2 regression suite generated by Sentinel. You receive:

1. **original_test** — an existing PHPUnit + Guzzle API test that was previously generated by Sentinel.
2. **change_reason** — a one-sentence explanation of *why* this test is now stale or insufficient, referencing the specific lines that changed.
3. **diff_excerpt** — the unified diff showing what changed in the source code this test exercises.
4. **new_source_code** — the full post-diff source file(s) that the test exercises.

Your task: rewrite the test class so it remains valid against the new code and maximises coverage of the changed behaviour. Rules:

- Preserve the class name, namespace, setUp(), and authenticate() helpers exactly.
- Update assertions that are now wrong due to the change. Do NOT remove assertions that are still correct.
- Add at least one new test method for each new behaviour, boundary, or error path introduced by the diff.
- Add a `// SENTINEL-UPDATED:` comment on each changed or added line explaining what changed and why in one sentence.
- Keep the PHPUnit + Guzzle pattern and coding style identical to the original test.
- Output ONLY the complete, valid PHP file — no markdown fences, no explanation outside the file.

<?php
/**
 * Generated by Sentinel · Stage 3 · Test Generation
 * Intent:  TI-010 — Payment method deletion blocked by open order (payment)
 * Level:   api
 * Source:  StripeIntegration\Payments\Controller\Customer\PaymentMethods

namespace Sentinel\Tests\Api;

use GuzzleHttp\Client;
use PHPUnit\Framework\TestCase;

class PaymentMethodDeletionTest extends TestCase
{
    private Client $client;
    private string $token;

    protected function setUp(): void
    {
        $this->client = new Client([
            'base_uri'    => $_ENV['MAGENTO_BASE_URL'],
            'http_errors' => false,
        ]);
        $this->token = $this->authenticate(
            $_ENV['TEST_PRIMARY_USER_EMAIL'],
            $_ENV['TEST_PRIMARY_USER_PASSWORD']
        );
    }

    private function authenticate(string $email, string $password): string
    {
        $resp = $this->client->post('/rest/V1/integration/customer/token', [
            'json' => ['username' => $email, 'password' => $password],
        ]);
        $this->assertSame(200, $resp->getStatusCode(), 'Auth failed');
        return trim(json_decode((string) $resp->getBody(), true), '"');
    }

    public function testCannotDeleteCardWithOpenOrder(): void
    {
        $resp = $this->client->delete('/stripe/customer/deleteCard', [
            'headers' => ['Authorization' => 'Bearer ' . $this->token],
            'json'    => ['token' => 'pm_test_pending_order'],
        ]);
        $this->assertSame(403, $resp->getStatusCode());
        $body = json_decode((string) $resp->getBody(), true);
        $this->assertStringContainsString('open order', strtolower($body['message'] ?? ''));
    }

    public function testCanDeleteCardWithNoOrders(): void
    {
        $resp = $this->client->delete('/stripe/customer/deleteCard', [
            'headers' => ['Authorization' => 'Bearer ' . $this->token],
            'json'    => ['token' => 'pm_test_no_order'],
        ]);
        $this->assertSame(200, $resp->getStatusCode());
    }
}

### Input: change_reason
`PaymentMethods::delete` added `'complete'` to the blocked-statuses array, meaning cards tied to completed orders can no longer be deleted. Previously only processing/pending/holded orders blocked deletion. Also `$token = trim($token)` was added, so tokens with surrounding whitespace are now silently normalised before lookup — the original test did not cover whitespace-padded tokens at all.
